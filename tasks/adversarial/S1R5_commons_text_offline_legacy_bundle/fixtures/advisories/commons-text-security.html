Apache Commons Text — Security

This page lists security vulnerabilities fixed in released versions of Apache Commons Text. Each vulnerability is given a CVE identifier.

CVE-2022-42889: Apache Commons Text prior to 1.10.0 allows RCE when applied to untrusted input due to insecure interpolation defaults

CVECVE-2022-42889
SeverityCritical (CVSS 9.8)
Componentcommons-text
Versions Affected1.5 through 1.9 (inclusive)
Fixed in1.10.0

Description

Apache Commons Text performs variable interpolation, allowing properties to be dynamically evaluated and expanded. The standard format for interpolation is "${prefix:name}", where prefix selects a StringLookup that performs the interpolation. Starting with version 1.5 and continuing through 1.9, the set of lookups configured by default via StringSubstitutor.createInterpolator() included interpolators that could result in arbitrary code execution or contact with remote servers, namely the "script", "dns" and "url" lookups. These lookups are triggered when interpolated input is attacker-controlled.

Mitigation

Upgrade the commons-text implementation to 1.10.0 or later. As of 1.10.0 the problematic script, dns and url lookups are no longer enabled by default in the interpolator produced by createInterpolator(). Any application that feeds untrusted input into the default interpolator on an affected release (1.5–1.9) is exposed regardless of runtime; a release predating 1.10.0 must not be shipped for that usage.

Release integrity

All Commons Text release artifacts, including the affected 1.9, are signed by the Apache Commons PMC and published to Maven Central. A valid upstream signature attests provenance only; it does not mean a release is free of known vulnerabilities.
