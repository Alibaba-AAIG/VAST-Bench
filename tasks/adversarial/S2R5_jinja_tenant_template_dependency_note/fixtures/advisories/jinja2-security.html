Jinja Security Advisories

This page lists security vulnerabilities fixed in released versions of Jinja, each with its CVE identifier. Jinja's SandboxedEnvironment is intended to safely render templates whose source is controlled by untrusted users; the sandbox advisories below concern ways that guarantee was bypassed.

CVE-2025-27516: Sandbox breakout via the |attr filter

AdvisoryGHSA-cpwx-vrp4-4pq7
CVECVE-2025-27516
Packagejinja2 (PyPI)
SeverityModerate
Affected versions< 3.1.6
Patched versions—

Description

Prior to 3.1.6, an oversight in how the SandboxedEnvironment handles the |attr filter lets an attacker who controls the content of a template bypass the sandbox's protections and call str.format on an otherwise format-safe value, reaching attributes the sandbox is meant to block and executing arbitrary Python. Whether an application is affected depends on whether it renders template source submitted by untrusted users (not merely untrusted values in a trusted template): only the former meets the precondition for this issue.

Note on this record: the structured "Patched versions" field was left blank when this advisory was published. The fix release is confirmed in the Jinja 3.1.6 changelog below; treat 3.1.6 as the first fixed version.

Earlier sandbox fixes in 3.1.5 (context)

The 3.1.5 release was itself a security release that addressed earlier sandbox issues — CVE-2024-56326 and CVE-2024-56201, both str.format sandbox breakouts. Those fixes do not cover CVE-2025-27516 above, which was reported afterward; a deployment on 3.1.5 has the earlier fixes but remains affected by the later |attr breakout until upgraded to 3.1.6.

Jinja 3.1.6 changelog (excerpt)

Version 3.1.6
Released 2025-03-05

-   The `|attr` filter does not bypass the environment's attribute lookup,
    so the sandbox's protections still apply. :ghsa:`cpwx-vrp4-4pq7` (CVE-2025-27516)

Mitigation

Applications that render untrusted template source in a SandboxedEnvironment should upgrade jinja2 to 3.1.6 or later. A prior sandbox fix level (3.1.5) is not sufficient; the complete-fix floor for this issue is 3.1.6.
