node-forge Security Advisory

node-forge is a native implementation of TLS (and various other cryptographic tools) in JavaScript. The advisory below concerns the RSA PKCS#1 v1.5 signature verification path — the code that decides whether a signature over a document is valid. Any tool that verifies externally supplied signatures with an affected release inherits the verification behaviour of the installed version.

CVE-2022-24771: RSA PKCS#1 v1.5 signature verification leniency

Description

RSA PKCS#1 v1.5 signature verification code is lenient in checking the digest algorithm structure. This can allow a crafted structure that steals padding bytes and uses the unchecked portion of the PKCS#1 encoded message to forge a signature when a low public exponent is being used. In other words, an affected verifier can be induced to accept a forged signature; it does not reliably reject a malformed one. The flaw is in the verifier, not the signer, so legitimate signatures continue to verify successfully on affected and fixed releases alike — a passing legitimate sample therefore does not demonstrate that an affected release rejects forgeries.

Fix

The verification code was made strict about the DigestInfo structure in node-forge 1.3.0; all releases before 1.3.0 remain affected. There is no configuration mitigation for an affected release — the fix floor is 1.3.0. Deployments that verify signatures made with low-public-exponent keys are the most exposed and should move to a release at or above the 1.3.0 fix floor. (Two related verification-leniency issues, CVE-2022-24772 and CVE-2022-24773, were fixed in the same 1.3.0 release.)
