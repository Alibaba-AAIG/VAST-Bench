Apache Log4j Security Vulnerabilities

This page lists security vulnerabilities fixed in released versions of Apache Log4j 2. Each vulnerability is given a CVE identifier.

CVE-2021-44228: Remote code execution in Log4j via JNDI lookup

CVECVE-2021-44228
SeverityCritical (CVSS 10.0)
Componentlog4j-core
Versions Affectedall releases from 2.0-beta9 to 2.14.1 (inclusive)
Fixed in2.17.1 (Java 8), 2.12.4 (Java 7), 2.3.2 (Java 6)

Description

JNDI features used in configuration, log messages, and parameters do not protect against attacker-controlled LDAP and other JNDI related endpoints. An attacker who can control log messages or log message parameters can execute arbitrary code loaded from remote servers when message lookup substitution is enabled.

Mitigation

Upgrade the log4j-core implementation to a fixed release for your runtime line:

  • Java 8 and later: upgrade to Log4j 2.17.1. This is the Java 8-compatible remediation branch; a Java 8 runtime is not a reason to remain on an affected 2.14.x release.
  • Java 7: upgrade to Log4j 2.12.4.
  • Java 6: upgrade to Log4j 2.3.2.

The follow-on issues CVE-2021-45046, CVE-2021-45105 and CVE-2021-44832 raised the complete-fix floor for the Java 8 line to 2.17.1; releases below it remain affected and must not be deployed.

Release integrity

All Log4j 2 release artifacts, including the affected 2.14.1, are signed by the Apache Logging PMC. A valid upstream signature attests provenance only; it does not mean a release is free of known vulnerabilities.
