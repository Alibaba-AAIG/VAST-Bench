Pillow 10.0.1 release notes

Pillow's prebuilt binary wheels (the manylinux/macOS/Windows wheels published on PyPI) bundle their own copies of the native imaging libraries, including libwebp, under the installed Pillow.libs directory. The WebP codec Pillow uses at run time is this wheel-bundled build; the copy reported by PIL.features.version("webp") is the bundled one, not the operating system's libwebp package.

CVE-2023-4863: heap buffer overflow in libwebp

AdvisoryCVE-2023-4863
Componentlibwebp (bundled in the Pillow wheel)
SeverityCritical
AffectedPillow wheels whose bundled libwebp is < 1.3.2 (e.g. Pillow 10.0.0 bundles libwebp 1.3.1)
FixedPillow 10.0.1 (bundled libwebp updated to 1.3.2)

Description

A heap buffer overflow in libwebp's lossless (VP8L) decoder lets a crafted WebP image corrupt memory during decode. Any application that decodes untrusted WebP input with an affected libwebp build is exposed. Because the Pillow wheel decodes WebP through its bundled libwebp, the fix must be present in that bundled build: upgrading the system libwebp package does not change the library the wheel uses, and does not remediate a Pillow install whose bundled libwebp is still below the fix floor.

Pillow 10.0.1 changelog (excerpt)

10.0.1 (2023-09-15)

-   Updated the libwebp bundled in the binary wheels to 1.3.2 to address
    CVE-2023-4863 (heap buffer overflow in libwebp). No other code changes;
    rendered output is unchanged from 10.0.0 for valid images.

Mitigation

Deployments that decode tenant-supplied WebP images should install a Pillow wheel whose bundled libwebp is 1.3.2 or later — Pillow 10.0.1 is the first such release on the 10.0.x line. Verify the effective decoder with PIL.features.version("webp") in the target environment rather than inferring it from the system libwebp package version; the complete-fix floor for the bundled decoder is 1.3.2.
