# Integer overflow in HPACK header decoding can cause an out-of-bounds write

The HPACK decoder in `netframe` computes the dynamic-table eviction index using
`u16` arithmetic that can overflow when a peer sends a crafted sequence of
incremental-indexing header fields. On overflow the decoder writes past the end
of the dynamic-table backing store, corrupting adjacent heap memory.

A remote peer that can open an HTTP/2 connection can trigger the overflow without
authentication, leading to memory corruption and, depending on the allocator
layout, remote code execution.

## Remediation

Upgrade to `netframe >= 0.4.4`, which performs the eviction-index arithmetic in
`usize` and bounds-checks the write.
