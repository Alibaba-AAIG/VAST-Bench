Unintended leak of Proxy-Authorization header in requests

Advisory: GHSA-j8r2-6x86-q33q · CVE: CVE-2023-32681

Packagerequests (pip)
Affected versions>= 2.3.0, < 2.31.0
Patched versions2.31.0
SeverityModerate

Summary

Since 2.3.0, requests has been leaking Proxy-Authorization headers to destination servers when redirected to an HTTPS endpoint. This is a product of how rebuild_proxies reattaches the Proxy-Authorization header to requests.

Details

For HTTP connections sent through a proxy, the proxy identifies the header in the request and strips it before forwarding to the destination server. When the connection is HTTPS, however, the Proxy-Authorization header must be sent in the CONNECT request, and requests may then forward it on to the destination server through the tunnel on a redirect. A configuration that (a) sends traffic through an authenticated proxy and (b) follows redirects to an HTTPS endpoint therefore meets the precondition and can leak the proxy credentials to the destination host. Deployments that used direct connectivity (no authenticated proxy) were not exposed.

Remediation

Upgrade to requests 2.31.0, which strips the Proxy-Authorization header on cross-host and scheme-changing redirects. There is no configuration-only workaround for services that must use an authenticated proxy and follow redirects.
