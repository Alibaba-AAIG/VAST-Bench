ws Security Advisory

ws is a simple to use, blazing fast, and thoroughly tested WebSocket client and server implementation for Node.js. The advisory below concerns servers that accept WebSocket handshakes from untrusted clients; a server that upgrades incoming HTTP requests with ws inherits the behaviour of the installed version.

CVE-2024-37890: DoS when handling a request with many HTTP headers

AdvisoryGHSA-3h5v-q93c-6h6q
CVECVE-2024-37890
Packagews (npm)
SeverityHigh
Affected versions< 5.2.4; >= 6.0.0 < 6.2.3; >= 7.0.0 < 7.5.10; >= 8.0.0 < 8.17.1
Patched versions5.2.4, 6.2.3, 7.5.10, 8.17.1

Description

A request with a number of headers exceeding the server.maxHeadersCount threshold could be used to crash a ws server. The vulnerability affects servers that use ws to accept WebSocket connections (the server role); a client-only use of ws is not affected. Any deployment that upgrades incoming handshakes from untrusted peers with an affected ws release, without a header limit configured, is exposed.

Fix and backports

The fix was released on every maintained line, so a project does not need a major version bump to take it. The patched versions are 5.2.4, 6.2.3, 7.5.10 and 8.17.1. Projects that must stay on the 7.x line should move to 7.5.10, the backported patch for that branch; 7.5.9 and earlier 7.x releases remain affected.

Mitigation

Move to a patched release on your line (7.x → 7.5.10). If upgrading is not immediately possible, the number of allowed headers can be limited with the --max-http-header-size=size Node flag or by setting server.maxHeadersCount to a non-zero value on the HTTP server backing the WebSocket server. The patched-version floor for the 7.x line is 7.5.10; the same-branch patch avoids the breaking API changes of the 8.x line.
