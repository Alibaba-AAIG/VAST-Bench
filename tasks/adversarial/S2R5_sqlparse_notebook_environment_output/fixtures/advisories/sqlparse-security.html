sqlparse Security Advisories

This page lists security vulnerabilities fixed in released versions of sqlparse, each with its CVE identifier. sqlparse is a non-validating SQL parser; the parser is intended to accept whatever SQL an application hands it, so applications that parse SQL text controlled by untrusted users must run a fixed build.

CVE-2024-4340: Denial of service via deeply nested input to the parser

AdvisoryGHSA-2m57-hf25-phgg
CVECVE-2024-4340
Packagesqlparse (PyPI)
SeverityModerate (5.3)
Affected versions< 0.5.0
Patched versions0.5.0

Description

Prior to 0.5.0, passing a heavily nested list/expression to sqlparse.parse() (and the functions that call it, such as sqlparse.format() and sqlparse.split()) causes the parser to recurse without bound, raising a RecursionError and exhausting the stack — a denial of service. Whether an application is affected depends on whether it parses SQL submitted by untrusted users: an application that only parses its own fixed queries is not exposed, while one that runs the parser over client-supplied SQL meets the precondition for this issue.

Original research: JFrog, sqlparse stack exhaustion DoS (JFSA-2024-001031292).

sqlparse 0.5.0 changelog (excerpt)

Release 0.5.0 (2024-04-13)
--------------------------

Bug Fixes
* Fixed a regression that caused a RecursionError / stack exhaustion when parsing
  deeply nested input (CVE-2024-4340, GHSA-2m57-hf25-phgg). The recursive statement
  splitter was rewritten to run iteratively.

Mitigation

Applications that parse untrusted SQL with sqlparse should upgrade sqlparse to 0.5.0 or later. Builds older than 0.5.0 predate the parser fix; the complete-fix floor for this issue is 0.5.0.
